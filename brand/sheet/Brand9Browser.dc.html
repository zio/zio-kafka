One file serves both themes, so there is no dark variant to keep in sync.

9.3
Markup and test checklist
HTML head
<!-- in <head>, on every docs page --> <link rel="icon" href="/favicon.svg" type="image/svg+xml"> <link rel="icon" href="/favicon.ico" sizes="32x32"> <link rel="apple-touch-icon" href="/apple-touch-icon.png"> <link rel="manifest" href="/site.webmanifest"> <meta name="theme-color" content="#FFFFFF" media="(prefers-color-scheme: light)"> <meta name="theme-color" content="#101521" media="(prefers-color-scheme: dark)">
site.webmanifest
{ "name": "ZIO Kafka", "short_name": "ZIO Kafka", "icons": [ { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" }, { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }, { "src": "/icon-maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" } ], "theme_color": "#101521", "background_color": "#FFFFFF", "display": "browser" }
Before release, check
Light and dark tab strip, active and inactive tab
20 or more tabs open: icon only, still easy to find
Pinned tab and a bookmark without a name
1× and 2× screens (the 16 and 32 px sizes in favicon.ico)
A browser without SVG favicons falls back to favicon.ico
iOS home screen: apple-touch-icon.png, square corners in the file
Android: the maskable icon keeps the rings inside the safe circle
Slack, Discord and X link previews pick up social-og-*.png
The SVG link comes first; browsers that read SVG favicons take it, the rest fall back to the ICO. Theme colour follows the page ground, white in light mode and ink in dark mode, so the browser chrome does not turn orange.
